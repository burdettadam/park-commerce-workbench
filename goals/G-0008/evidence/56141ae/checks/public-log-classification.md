# Public hosted-log classification

Source S: `56141ae40f05704ff0ae30b232ef878e2943b6c6`; free public run `38478861553`. The contract reviewer noticed `Using generated security password` lines in the full public Java job log. I inspected the downloaded full job log locally without copying password values into goal artifacts. It contains six such messages emitted by Spring Boot `UserDetailsServiceAutoConfiguration` during catalog, pricing and booking integration test process startup. They are generated runtime defaults in disposable test contexts, not a `DEMO_*` token, repository secret, user credential, customer datum, or persisted application record. The test processes exited with the job. No service deployment or shared runtime was part of this run.

The selected public `checks/hosted-ci.txt` and `checks/hosted-junit.txt` do not reproduce those values. The complete job log is nevertheless publicly accessible at the linked run, so the values should not be described as withheld or secret. The classification is **ephemeral test-generated values with no surviving access target**. I found no evidence that a real bearer credential was exposed. Future log hygiene could suppress the unused auto-configuration message, but this observation does not alter the G-0008 pricing or quote contract and does not establish a product defect.
