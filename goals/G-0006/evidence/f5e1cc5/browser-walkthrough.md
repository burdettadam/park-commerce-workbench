# G-0006-A02 — employee to guest event purchase

Source S `f5e1cc5e576c45a785199374031e5853a4dc7606`, clean detached verification worktree `.tmp/g0006-live`. The Vaadin console used `http://127.0.0.1:8480/`; Angular used `http://127.0.0.1:4300/`; APIs used loopback ports 8381–8383. Local Playwright 1.64.0 drove installed headless Chromium. This was an actual browser session against the actual Compose services, not a DOM mock or screenshot of source. The exact executed script is [checks/browser-flow.cjs](checks/browser-flow.cjs); [raw steps](checks/browser-flow.txt) retain the command, source, timestamps, assertions and synthetic IDs. The ignored `.env` supplied randomly generated local demo credentials in process memory; its values are absent from the reports.

1. Open the employee console, enter the local employee token, set product ID `g6-event-65db25a9` and fictional name, save draft version 1, then click **Publish reviewed saved draft**. A public catalog API read returned revision 1. Through the same UI, publish price book version 1 at $100 adult / $70 child, and create event `g6-occurrence-65db25a9` for `2026-10-20` with capacity 3. [Employee browser screenshot](checks/screenshots/admin.png).
2. Open the Angular guest client in a second page, enter the guest token and authenticate against the booking service. Load published products, select that product and date, and click **Get itemized quote**. The GraphQL response returned quote `37fbc3dd-9c11-4903-a176-cfecd4c8c5e0`, pricing version 1, total 10000 cents. The UI displayed $100. [Original quote screenshot](checks/screenshots/quote.png).
3. Return to the employee browser, change pricing version to 2 and adult rate to $125, then publish through Vaadin. Reread the original quote through the pricing API: version 1 and 10000 cents. A new quote for the other demo guest returned 12500 cents. The original guest UI still displayed $100 before holding inventory.
4. In Angular, enter matching occurrence ID, click **Hold event capacity**, then **Confirm saved simulated purchase**. The receipt and booking API returned order `38bc4892-f810-42b0-90fd-5ae9413b858e`, one ticket, 10000 cents. Click **Retry same checkout**; a second order read was deeply equal to the first. [Confirmed order screenshot](checks/screenshots/order.png). The booking availability read after retry and restart reported capacity 3, confirmed 1, held 0, available 2; see [restart evidence](restart-and-limitations.md).

The screenshots show synthetic IDs and masked password fields. They were inspected before publication.
