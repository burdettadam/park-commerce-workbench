The Vaadin console used `http://127.0.0.1:8480/`; Angular used `http://127.0.0.1:4300/`; APIs used loopback ports 8381–8383. Local Playwright 1.64.0 drove installed headless Chromium. This was an actual browser session against the actual Compose services, not a DOM mock or screenshot of source. The exact executed script is [checks/browser-flow.cjs](checks/browser-flow.cjs); [raw steps](checks/browser-flow.txt) retain the command, source, timestamps, assertions and synthetic IDs. The ignored `.env` supplied randomly generated local demo credentials in process memory; its values are absent from the reports.

1. Open the employee console, enter the local employee token, set product ID `g6-event-e1238acb` and fictional name, save draft version 1, then click **Publish reviewed saved draft**. A public catalog API read returned revision 1. Through the same UI, publish price book version 1 at $100 adult / $70 child, and create event `g6-occurrence-e1238acb` for `2026-10-20` with capacity 3. [Employee browser screenshot](checks/screenshots/admin.png).
2. Open the Angular guest client in a second page, enter the guest token and authenticate against the booking service. Load published products, select that product and date, and click **Get itemized quote**. The GraphQL response returned quote `98cf4bd3-8e67-4452-aac3-65f0946a74b0`, pricing version 1, total 10000 cents. The UI displayed $100. [Original quote screenshot](checks/screenshots/quote.png).
3. Return to the employee browser, change pricing version to 2 and adult rate to $125, then publish through Vaadin. Reread the original quote through the pricing API: version 1 and 10000 cents. A new quote for the other demo guest returned 12500 cents. **After publication**, read the original guest page's visible total element and assert it is `$100.00 USD`; then capture the [post-publication screenshot](checks/screenshots/reprice.png). The screenshot has the same bytes as the earlier quote screenshot because that guest DOM remained unchanged. The ordered assertion and API responses in the [browser script](checks/browser-flow.cjs) and [run output](checks/browser-flow.txt) establish when the observation occurred.
4. In Angular, enter matching occurrence ID, click **Hold event capacity**, then **Confirm saved simulated purchase**. The receipt and booking API returned order `5a2d529d-3af9-4121-a508-c1a458e30b26`, one ticket, 10000 cents. Click **Retry same checkout**; a second order read was deeply equal to the first. [Confirmed order screenshot](checks/screenshots/order.png). The booking availability read after retry and restart reported capacity 3, confirmed 1, held 0, available 2; see [restart evidence](restart-and-limitations.md).

The first review found that the earlier script read guest text before the price change, so its claim about the post-publication UI was unsupported.
