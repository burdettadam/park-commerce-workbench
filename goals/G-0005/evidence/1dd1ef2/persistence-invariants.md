# G-0005-A02 — actual datastore invariants

All named tests ran against disposable MongoDB 8.0.26 or MySQL 8.4.11 Testcontainers at fixed S `1dd1ef28d3d5db6bcd4e47255c074ed6205c1627`; counts and raw Failsafe reports are in [A01](database-tests.md). The test names identify assertions, not merely compiled source.

| Criterion | Executed assertions |
| --- | --- |
| AC02 catalog versions | `MongoCatalogIT.recreatedMongoAdapterRetainsDraftAndHistoryIdentities`, `snapshotsRoundTripAndAggregateLatest`, `indexRejectsDuplicateRevision`, and `draftUniqueIndexRejectsDuplicateContentVersion` read the saved versions after a new adapter and reject duplicate MongoDB revisions/drafts. |
| AC02 price/quote snapshots and money | `JpaPricingIT.immutableQuoteAndMoneyRoundTrip` reads price-book version 1 and a quote from MySQL, verifies exact 10,000-cent total, catalog/pricing version 1 and `2030-10-31` visit date, publishes version 2 at 12,500 cents, then verifies the old quote remains unchanged and the new quote has version 2 and exact 12,500-cent total. `QuoteContractIT.realJsonAndGraphQlProduceTheIndependentHalfCentFixture` checks exact 10/2/8-cent subtotal/discount/total in real HTTP and stored quote paths. |
| AC02 dates and identifiers | `QuoteContractIT.parkLocalMidnightEligibilityIsConsistentThroughHttp` accepts the date at `2030-11-01T03:59:59.999Z` and rejects it at `04:00:00Z` for the park time zone. `JdbcBookingIT.expiryAndCaseSensitiveKeysArePreserved` stores distinct `Key` and `key` orders. `AdmissionCheckoutIT.binaryIdentifiersKeepCaseAndTrailingOwnerSpaceDistinct` checks case and owner-byte distinctions in the admission table. |
| AC03 rollback on unique conflict | `JdbcBookingIT.uniquenessConflictRollsBackAcrossSeparateRealConnections` holds open an observer MySQL connection, records its `CONNECTION_ID()`, and confirms a second event through the adapter on a different connection. A duplicate `(owner,idempotency_key)` conflicts after the adapter attempts the hold-status update. The observer sees the second hold still `ACTIVE` and zero orders for that event; availability remains 2 of 3 and the first event retains its one order. `failedCrossEventKeyReuseRollsBackHoldStatus` provides a second adapter-level rollback case. |
| AC03 other uniqueness/capacity | `JdbcBookingIT.concurrentSqlTransactionsCannotOversell` allows exactly 3 winners at capacity 3, `concurrentSqlCheckoutIsIdempotent` produces one order under concurrent retries, and `oneQuoteCannotHoldTwoEvents` leaves the other event at full availability. |

The separate-connection test uses `DataSource.getConnection()` for the observer and Spring's transaction-bound JDBC connection for the adapter, asserts their MySQL connection IDs differ, and queries the observer after the conflict. This verifies committed MySQL state rather than trusting an in-memory ledger object. It does not claim Aurora behavior or process-durability guarantees.
