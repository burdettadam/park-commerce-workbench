# M2 — Complete catalog and pricing administration

**Status: proposed milestone, not achieved.** Owner/acceptance authority is to be recorded when adopted. No deadline, release tag, human approval or cloud authorization is asserted.

## Observable milestone outcome

An employee can draft, preview, publish, and explain versioned prices without rewriting existing quotes.

## Milestone artifacts

Publication audit; preview scenarios; deterministic pricing fixture pack.

Each goal must identify a fixed source candidate, expected results, actual checks, independent reviewer findings, intended-use decision and recoverable handoff while its PR is open. Record concise results and links in the PR or goal record; keep generated outputs in ignored local paths and remove them after the feature merges. Goal-specific filenames in proposal cards are legacy examples, not required committed outputs.

## Exit gate

All three goals must have a current `ready` candidate under the adopted rules, with every acceptance criterion and required observation accounted for. The integration owner identifies exactly which source revisions enter the combined milestone candidate and reruns affected end-to-end checks on that combination. Passing each branch separately is insufficient.

Record one concise milestone acceptance decision in the PR or source goal record using [the template](../templates/milestone-acceptance.md) as a checklist. The human records intended-use acceptance and unresolved operational limitations. No missing licensed tool, skipped database suite, stale review or unavailable artifact is silently waived. A material change requires an accepted revision and renewed affected evidence.

**Checkpoint meaning:** Pricing workbench demonstration.

`ready`, human-approved, merged, packaged, deployed, healthy and remotely recoverable are separate observations. Version-producing merges retain the human gate. No GitHub visibility change or external spending is authorized by milestone adoption.
