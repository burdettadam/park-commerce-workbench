# Park Commerce Workbench

An open source engineering portfolio for a fictional park commerce system. Employees can publish products and dated prices; guests can request itemized quotes, hold event inventory, and complete simulated, idempotent checkouts. Admission checkout issues dated entitlements without allocating event capacity.

This is a development workbench. It uses synthetic data and local demo authentication. It does not process payments or provide a production deployment.

## Quick start

Run the Java domain scenarios with JDK 21 and Bash:

```bash
bash scripts/test-core.sh --demo
```

For Maven, Node 24, Docker Compose, and the live service demo, follow [the setup guide](docs/START-HERE.md). Local credentials are generated by `scripts/configure-local.sh` into an ignored `.env`; the example environment file is safe to inspect and is not a deployed secret.

## Repository layout

| Path | Purpose |
| --- | --- |
| `core/` | Pure Java pricing, quote, hold, checkout, and entitlement rules |
| `catalog-service/`, `pricing-service/`, `booking-service/` | Spring APIs and database adapters |
| `service-support/` | Shared API errors, local authorization, and GraphQL limits |
| `admin-console/` | Optional Vaadin employee UI |
| `storefront/` | Angular guest UI and retry state |
| `contracts/`, `scripts/` | Contract fixtures, local setup, and verification |
| `docs/` | Architecture, product contracts, roadmap, and test evidence |

The proposed [roadmap](docs/roadmap/README.md) contains 10 milestones and 30 goals. Its proposals are planning input; they do not imply that a goal, independent review, or release has been accepted. The included agent guidance supports local development with Git and Codex; the application does not require the external `git-agent` initializer to build or run.

## Verify

```bash
bash scripts/verify.sh --integration
node --test scripts/pricing-contract.test.mjs
cd storefront && npm ci && npm run test:types && npm run build
```

The GitHub Actions workflow runs Java integration and client contract checks on pushes to `main` and on pull requests. The last verified private candidate passed 344 Java tests, including 64 database integration tests, plus the client and contract checks. Public CI must run on this new history before those results can be attributed to it. See [verification details](docs/import-verification-2026-10-12.md).

Local demo security is intentionally limited to loopback development. Review [security boundaries](docs/project/security.md) before running services. No production identity, payment processing, cloud deployment, or browser acceptance is claimed.
